# 拾声 XianDial · 固件

**一台不塞台源的 ESP32-S3 网络收音机固件。台源由你自己带进来。**

> 🌐 **English version: [README.en.md](README.en.md)** · 烧录步骤 / Flashing: [FLASHING.md](FLASHING.md)

让「听广播」回到本来的样子：开机、选台、出声。没有账号、没有推荐算法、没有开屏广告。

- 硬件：ESP32-S3 + 3.5 英寸 IPS TFT 触摸屏（480×320，ST77922 + FT5x06 电容触摸）
- 音频：I2S 功放，支持 MP3 / AAC / FLAC / OGG，HLS（m3u8）直播
- 台源：**从 TF 卡读你自己的台源清单**（本仓库内置 0 条，见下）
- 内存：LVGL 池 112 KB，PSRAM 8 MB

---

## 这个仓库的特点：台单是空的

**内置台单 0 条。** 这不是偷工，是刻意的：

1. 真实电台地址清单是这个项目最大的公开风险（来源与版权），放进公开仓库等于替第三方站点做分发；
2. 内置台单为了省内存统一用 `http` + `.ts` 切片，而**你自己的 M3U 绝大多数是 `https` + ADTS 裸 AAC** —— 两条路径差别很大，附一份「官方台单」反而会让你困惑。

所以分工是：**固件给接口，工具造台源，地址归你。**

### 你拿到的是什么

一份**能跑通全流程的固件**，不是一份「保证你的 M3U 全都能播」的承诺：

| | 状态 |
|---|---|
| 界面与交互（选台、播放页、收藏、历史、睡眠、配网） | ✅ 完整源码，随便改 |
| 播放实现（直连流 + HLS 直播 + 格式自适应） | ✅ 完整源码 |
| 台源导入接口（读卡 / 串口推卡 / 热重载） | ✅ 完整 |
| 你的 M3U 里有多少能播 | ⚠️ **取决于源本身**，见下面「能播多少」 |

**关于「能播多少」** —— 这件事不该含糊，所以给你算法，你自己算：

#### 你的 M3U 里有多少能播，取决于三个乘法因子

```
可播台数 ≈ 台单总数 × 格式支持率 × 服务器可达率 × https 通过率
```

| 因子 | 影响它的是什么 | 典型值 |
|---|---|---|
| **格式支持率** | 固件吃直连 MP3/AAC/FLAC/OGG 与 HLS（m3u8）。**不认** `.m3u`/`.pls` 列表、有声书、需要 Referer 头的、鉴权的、非标准封装的 | 85% 左右 |
| **服务器可达率** | 源站是否还活着、是否允许你的 IP、是否限速/限地区 | 70~85% |
| **https 通过率** | https 要占 TLS 缓冲。**本版已修**（v1.51 把 mbedTLS 单连接缓冲 16 KB→4 KB 并开启动态分配）。仍失败多半是证书链问题 | 修后接近 100% |

> ⚠️ **v1.50 及更早：https 台基本全挂。** 根因是内部 RAM 的**最大连续块**不够 TLS 用（不是 free 不够 —— 这两个数不一样，看 free 会得出相反结论）。那时发布等于只能听 http 台。**这一条已修**，你拿到的是修好的版本。

#### 一个真实的分布参考

作者自用的 1253 条台单（国内电台）实测构成：

| 类型 | 占比 | 能否播 |
|---|---|---|
| 直连 `.mp3` / `.aac` | 59.3% | ✅ 最稳 |
| HLS `.m3u8` | 28.4% | ✅ 可播，需服务器允许 |
| 无后缀（靠内容嗅探） | 12.3% | ⚠️ 五五开 |

**但你自己的 M3U 会不一样**：作者这份是「当年为省内存刻意全用 http」的产物，**98.7% 是 http**；而网上现存的、你能下到的 M3U 大多是 https。所以**你的播率大概率比这份台单更难**，先按 70% 做心理预期比较稳妥。

#### 播不了怎么定位

用串口分层测（**自编译版本**才有 `?insecure`；发布版把它去掉了）：

```
st_net http://你的源地址
```

日志会告诉你卡在哪一层：**DNS / TCP / TLS / HTTP / 解码**。前四层任何一个不通，都不是固件的锅 —— 是源本身的问题，或者服务器不让你连。

- `403` → 需要 Referer 或 UA 伪装，这类源本固件不支持
- `open 失败` + TLS 错误 → 证书链问题，源站证书过期或自签
- `200` 但 `#EXTM3U` 后就没数据 → 源挂着但没播
- 解码层报错 → 编码是本固件不处理的格式（如某些 WMA、AMR）

### 先装固件

**这一步跟「下载工具」是两件独立的事** —— 固件刷进芯片，工具在电脑上跑。

**你要准备：**

| 项 | 说明 |
|---|---|
| 一块 ESP32-S3 开发板 | 带 3.5" **IPS TFT** 电容触摸屏（480×320，驱动 ST77922 + FT5x06）。**本固件只适配这一种屏**，别的屏不工作 |
| 一根 USB 线 | 走板载 USB 口。**注意**：板载 Type-C 的 PHY 被 Serial-JTAG 占了，**不能**当 USB 主机用（插 U 盘/读卡器无效） |
| 一台电脑 | Windows / macOS / Linux 都行 |
| 一张 TF 卡 | 可选。没有卡也能用（走串口推卡，见下），但插卡更省事 |

#### 固件文件说明（★ 刷之前先看这一段，能避免砖机）

ESP32-S3 的 flash 里要放**三段**东西，各有固定地址：

| 地址 | 内容 | 文件 |
|---|---|---|
| `0x0` | 二级引导程序（bootloader） | `bootloader.bin` |
| `0x8000` | 分区表 | `partition-table.bin` |
| `0x10000` | 应用程序本体 | `xiandial-radio.bin` |

> ⚠️ **初学者最常踩的坑：把 `xiandial-radio.bin` 当成整包刷到 `0x0`。** 那样做等于把应用程序写进引导程序区，**板子起不来**（表现为串口无日志、屏幕全黑）。它只是三段中的一段，地址必须是 `0x10000`。

Release 里提供了两种刷法用的文件：

| 文件 | 用途 |
|---|---|
| **`XianDial-v1.51-merged.bin`** | ★ **推荐**。三段已合并成一个文件，烧录地址 `0x0`。不会刷错地址 |
| `xiandial-radio.bin` + `bootloader.bin` + `partition-table.bin` | 分段刷，需要自己填三个地址。Release 的 `FLASHING.md` 里有完整命令 |
| `XianForge.html` | 台源制作器（中文界面） |
| `XianForge.en.html` | 台源制作器（英文界面，导出格式完全相同） |
| `SHA256SUMS.md` | 每个资产的 SHA256，下载后先核对再刷 |

**刷固件（三种方式，选一种）：**

**方式 A —— 网页烧录（最省事，不用装任何东西）**

打开 [ESP Web Tools](https://espressif.github.io/esptool-js/) →
点 `Connect` → 选你的串口 → 选 Release 里的 **`XianDial-v1.51-merged.bin`** →
芯片型号选 **ESP32-S3**，地址 `0x0`，`Start`。

> 用合并镜像时地址就是 `0x0`，一把刷完，不用管三段的事。**只有在你手里只有 `xiandial-radio.bin` 单个文件时**，才需要用方式 B 的三段命令。

**方式 B —— 命令行（推荐，能反复刷）**

```bash
# 装工具（只需一次）
pip install esptool

# 看串口号（Windows：COM3；macOS：/dev/cusbmodem*；Linux：/dev/ttyACM*）
esptool.py --list-ports

# 换固件版本时建议先擦除，避免旧分区表/配置残留
esptool.py --chip esp32s3 --port COM3 erase_flash

# —— 刷法 B1：合并镜像（一行，推荐）——
esptool.py --chip esp32s3 --port COM3 --baud 460800 \
    write_flash 0x0 XianDial-v1.51-merged.bin

# —— 刷法 B2：只有三个分段文件时（三行，地址必须对）——
esptool.py --chip esp32s3 --port COM3 --baud 460800 write_flash \
    0x0     bootloader.bin \
    0x8000  partition-table.bin \
    0x10000 xiandial-radio.bin

# 打开串口看日志（正常启动会打印台单数量、WiFi 状态）
esptool.py --chip esp32s3 --port COM3 monitor
```

**方式 C —— 自己从源码编译**（想改 UI / 加格式才需要）

需要 [ESP-IDF 6.0 以上](https://docs.espressif.com/projects/esp-idf/zh_CN/latest/esp32s3/get-started/index.html)（本工程编译于 6.1）：

```bash
git clone <this repo> && cd xiandial-radio
idf.py set-target esp32s3
idf.py -p COM3 build flash monitor
```

**刷完之后：**

1. 屏幕上出现配网页面提示 → 用手机连它广播的热点（`XianDial-XXXX`），浏览器打开 `http://192.168.4.1` 填 WiFi 名称密码
2. 没配网也能继续 —— 机器保持「0 台」等你导入台源，不会白屏

⚠️ **刷固件会覆盖芯片原有程序。** 分区表里**没有 OTA**，所以每次升级都要重新刷一次。

### 加台：三步

```
①  用 tools/XianForge.html 把你的 M3U / TXT 转成 stations.tsv
②  复制 stations.tsv 到 TF 卡根目录
③  插卡开机 —— 机器自动读
```

没有卡、卡读不出、文件格式不对，都不会白屏，机器保持「0 台」并提示导入。

热重载：卡插着也能改。用串口发 `st_put stations.tsv` 覆盖，或发 `st_reload` 让它重读（不用重启）。

**收藏栏第一次开机是空的**，这是预期行为 —— 本仓库台单是空的，作者的收藏名单没有随包发布。导入你自己的 `stations.tsv` 之后，在播放页按收藏键就能把台存进去，之后一直都在。

## 硬件规格

作者自用机的实测配置。**这份固件只在这套硬件上验证过** —— 换屏、换触摸控制器、换音频通路都需要改代码。

| 项 | 规格 |
|---|---|
| 主控 | **ESP32-S3**（RISC-V，512 KB SRAM，8 MB PSRAM） |
| 屏幕 | **3.5 英寸 IPS TFT**，480×320，**ST77922** 驱动，SPI 接口 |
| 触摸 | **FT5x06** 电容触摸（I2C），5 点 |
| 音频 | I2S DAC → 功放（吃 **+5V**），单声道喇叭 4Ω 3W |
| 存储 | 板载 **TF 卡座**（SDIO）；16 MB flash 用于固件 |
| 网络 | 2.4 GHz WiFi + 蓝牙（ESP32-S3 内置） |
| 电源 | 3.7 V 锂电池 + LDO，全程 LDO ⇒ 1000 mAh 约 2 小时 |
| 待机 | Deep sleep，**仅 IO0~21 可唤醒**（BOOT 键 = IO0） |
| 配网 | **SoftAP + captive portal**（因为扩展 IO 45/46 不能唤 deep sleep） |
| 框架 | ESP-IDF 6.1 + LVGL 9（LV_MEM_SIZE = 112 KB） |
| 分区 | 无 OTA，升级需重新烧录 |

**已知硬件限制（换板子前必读）：**

- 板载 Type-C 的 USB PHY 被 Serial-JTAG 占用，**当不了 USB 主机**（外接 U 盘 / 读卡器无效），要读写 TF 卡请走 WiFi 或用板载卡座。
- TF 卡走 **SDIO**，插在 Windows 上读不出来。台式机请用 USB 读卡器（Windows 能看到 `XianDial-XXXX` 热点）。
- 关机依赖 Q3 栅极未接 MCU 的硬件设计 ⇒ **任何 GPIO 都切不断电**，关机只是关屏 + 关 WiFi + deep sleep。

---

路径必须是 **`/sdcard/stations.tsv`**（TF 卡根目录）。

```
台名<TAB>栏目<TAB>地区<TAB>URL
```

硬性要求：

| 项 | 要求 |
|---|---|
| 编码 | UTF-8 **无 BOM** |
| 换行 | LF（不要 CRLF） |
| 分隔 | **TAB**（不是空格） |
| 行数上限 | 2000 |
| 空行 / `#` 开头 | 忽略，可作注释 |

行内多余空格会被去掉；`URL` 必须在第 4 列，不能含 TAB。

**为什么 BOM 和 CRLF 这么重要**：带 BOM ⇒ 第一个台名多一个方块，收藏按名匹配永远存不上；CRLF ⇒ URL 尾部挂个 `\r`，症状是「别的台都好，就这几台不行」，极难查。

栏目与地区取值：

- 栏目（13）：`新闻综合` `交通台` `音乐` `文艺` `说书` `戏曲` `怀旧老歌` `网络台` `教育台` `电视伴音` `综合` `宗教` `境外新闻`
- 地区（42）：`北京` … `新疆` `中国台湾` `中国香港` `中国澳门` `其他华语` `北美` `欧洲` `日韩` `新马` `东南亚` `大洋洲` `海外中文`
- 地区留空或填 `其他` ⇒ 全国台

不确定就照抄样例里的写法，转换器会自己推断。

## 配套工具

### XianForge.html —— 台源制作器

**单文件 HTML，双击即用，不联网、不上传。** 位置：`tools/XianForge.html`（中文界面）/ `tools/XianForge.en.html`（英文界面）

**两个语言版本导出的是完全相同的文件格式** —— 里面的栏目名、地区名都是固件认的固定中文标识符，不是显示文案。所以英文界面导出的 `stations.tsv`，中文固件一样能读。

- 支持 M3U（`#EXTINF` 各种写法）与纯文本列表
- 自动识别 UTF-8 / GBK / UTF-16
- 按台名推断栏目与地区
- 按 URL 去重（同一电台的多个镜像源都会保留）
- 导出 `stations.tsv`

**改完工具先跑自检**（无需浏览器，只要装了 node）：

```bash
node tools/_xf_selftest.js
```

31 项断言，覆盖栏目推断（含「XX人民广播电台」这类最常见台名与电视伴音的优先级）、M3U 解析、URL 去重、TSV 四列合规，以及 CRLF / 尾部 CR / 缺台名 / 无 URL 行等边界。退出码非 0 就是有问题。

> 这个自检不是形式主义 —— 开发中它抓出过真 bug：栏目规则表里只列了「中央人民广播电台」一家，于是「北京人民广播电台」全被判成兜底的「综合」。编译零报错、界面也看不出来。

### _sd_push.py —— 串口推卡（可选，`tools/` 下）

板载 TF 走 SDIO，Windows 看不到这张卡；板载 Type-C 的 PHY 被 Serial-JTAG 占着，板子**不能**当 USB 主机。所以固件里做了串口通道，能直接读写卡：

```bash
pip install pyserial
python tools/_sd_push.py stations.tsv        # 推台单进卡（带流控与行数核对）
python tools/_sd_cmd.py   st_ls               # 列卡上文件
python tools/_sd_cmd.py   st_reload           # 重读台单并重建界面，不重启
```

固件支持的串口命令：`st_dump` `st_reload` `st_ls` `st_cat <f>` `st_rm <f>` `st_put <f>`（逐行下发，单行 `.` 结束）`st_play <下标>` `st_net <url>`（分层测网络）

写文件走「先写 `.tmp` 再改名」，中途断线不会留半个文件。

## 编译

```bash
git clone <this repo>
cd xiandial-radio
idf.py set-target esp32s3
idf.py build
idf.py -p COM3 flash monitor
```

要求 ESP-IDF **6.0 以上**（本工程编译于 **6.1**）。

> `main/idf_component.yml` 里写的是 `idf: ">=6.0"`。这不是随手填的：工程用到了 `esp_driver_i2s` / `esp_driver_sdmmc` / `esp_driver_ledc` / `esp_driver_usb_serial_jtag` 这几个独立 driver 组件，它们在 5.x 与 6.x 之间的挂载位置有差异，声明 5.x 会让使用者编到一半卡在 CMake 上。宁可要求高一点。

**仓库里有什么、没什么：**

| 内容 | 状态 |
|---|---|
| 应用源码、台源导入、UI、播放 | ✅ 完整 |
| 主字库 `xs_font_12/16/24` + `xs_font_cjk12` | ✅ 完整（Ark Pixel + 思源黑体，均 OFL-1.1） |
| 发布版空台单 `net_stations_pub.c` | ✅ 0 条 |
| 台名字库 `xs_font_pub_st12/16.c` | ✅ 通用汉字版（GB2312 一级 3755 字） |
| 真实台单、按真实台名烘的字库、字库源 TTF | ❌ 不含 |

### 关于台名字库：为什么有两套

台名来自运行时（你的 `stations.tsv`），编译期不知道会显示哪一条，所以要单独出一套字库。

| | 自用版 | 发布版（本仓库） |
|---|---|---|
| 文件 | `fonts/xs_font_st12/16.c` | `fonts/xs_font_pub_st12/16.c` |
| 字形来源 | **台单里出现过的字** | **GB2312 一级汉字 3755 字** |
| 是否入仓库 | ❌ 排除 | ✅ 包含 |
| 体积 | 1.00 MiB | 2.86 MiB |

**为什么不把自用版那套也放进来**：它是用真实的 1254 个台名里出现的字烘的字形。台单清空了、字库照旧进仓库，等于把整份台单以**字形**的形式留在固件里 —— 那不叫置空。

**两套的符号名故意相同**（都是 `xs_font_st12`），文件名不同。`main/CMakeLists.txt` 按 `net_stations_pub.c` 是否存在自动二选一，两套永不同时进编译。所以**UI 代码在两个版本里是同一份，一行都不用改**。

**字号档**：12px（台单网格、列表行）+ 16px（播放页大台名）。24px 那一档已删除 —— 它从来没有 label 用上（见 `ui_xiandial.c` 里的说明），留着只是白占 1.21 MiB 编译时间和仓库体积。

### 生僻台名显示成方块怎么办

发布版字库含 GB2312 一级 3755 字，覆盖现代中文日常用字的 99.7%。**绝大多数台名正常显示**。少数生僻字（GB2312 二级字、方言字、生造词）会显示为方块。

**按你自己的台单重新生成：**

```bash
# 1. 把你的 stations.tsv 放到 main/net_stations.c 的位置（或让脚本读它）
#    脚本 st_chars() 会扫 TSV + 地区名 + 栏目名三个来源
# 2. 生成（输出 xs_font_st12.c / xs_font_st16.c）
python ../gen_fonts_st.py
# 3. 删掉 main/net_stations_pub.c，让 CMake 走自用版分支
```

字数会按你的台单收窄，体积通常比发布版小。改完记得同步 `main/CMakeLists.txt` 里的文件列表（增删字库档位时漏改会报 `missing and no known rule to make it`）。

> 字库源 TTF（Ark Pixel / 思源黑体）不在仓库里，需要的话按 `firmware/gen_fonts.py` 顶部的说明自行获取，两份 OFL 授权文本已随包。

## 已知限制

- **分区表没有 OTA**。升级要重新烧录。
- **部分 M3U 源可能播不了。** 常见原因：证书链不匹配、需要 Referer 头、需要鉴权、非标准封装格式。逐个适配不现实，固件只能吃主流格式（直连 MP3/AAC/FLAC，HLS 直播）。
- **HLS 多码率流只取第一个变体**，不按带宽挑选。
- **深睡唤醒只支持 RTC IO0~21**。所以配网走 SoftAP + captive portal。
- **HLS 直播的滑动窗口**：分片会过期，直播源中断后重连可能需要等几秒。

这几条都是设计取舍，不是 bug 遗留。要改，源码都在。

## 改之前先跑检查

如果你打算改这份固件（换 UI、加台源格式、调节字号），先知道它现在是不是干净的：

```bash
node tools/_xf_selftest.js        # 台源工具 31 项断言
node tools/_xf_en_selftest.js     # 英文版工具 22 项断言（含两版产物互比）
```

> **英文版那条断言是本项目最要紧的一条**：它拿同一份 M3U，分别用中文版和英文版跑一遍导出，**逐字比对两个 `stations.tsv`**。
>
> 原因是英文版有个中文版没有的死法：把栏目名、地区名翻成英文。翻完之后 —— 导入不报错、界面正常、TSV 四列都对，但真机上全部落进兜底分类。这个 bug 骗得过所有"格式检查"，只有拿两份产物互比才抓得到。

英文版工具由脚本从中文版生成，不要手改英文版：

```bash
python tools/_make_xianforge_en.py    # ① 文案替换（含协议 token 保护 + JS 语法闸门）
python tools/_make_xianforge_en2.py   # ② 使用/FAQ/免责/关于 四页整块替换
python tools/_xf_en_residual.py       # ③ 列出仍为中文的可见文本，人工确认
```

> ③ 那一步不是形式主义。中文文案在源码里常被拆成 `'前半' + '后半'` 两段，
> 「整句话」这个概念在源码层面根本不存在 —— 生成脚本先把拼接折叠才拿得到完整句子。
> 漏掉的句子不会报错，只会静默地留在英文界面里。

固件仓库里还带了两个开发期用的检查脚本（在 `firmware/` 下，不属于 `xiandial-radio/` 仓库）：

| 脚本 | 作用 |
|---|---|
| `_release_check.py` | 上架前全部闸门：空台单、字库符号名与脱敏、泄漏扫描、工具自检（含英文版）、README 一致性、授权齐全 |
| `_release_gitscan.py` | 只扫「Git 实际会提交的文件」，并先自检扫描规则本身 |

> 两个脚本都内建了「拿已知答案验自己」的机制。开发中它们各抓出过真问题——一个是扫描器把 CSS 的 `font:13px` 当成本机路径，一个是发布版字库漏了 `-o` 后面的输出路径，还有一个是我自己的英文版生成脚本里硬编码了本机用户路径，被扫描器当场抓出来。**跑完没报错不等于检查通过，要看它自己的自检段。**

## 隐私（这一节是承诺，不是宣传语）

### 这台设备在网络上做什么

**全部行为就三件：**

1. 连**你家**的 WiFi（SoftAP 配网页，或读卡上的 `wifi.txt`）
2. 访问**你自己导入的电台流地址**（`stations.tsv` 里的 URL）
3. 向 `ntp.aliyun.com`（UDP/123）发**一次**时间同步请求

**没有第四件。** 具体说：

| 你可能担心的 | 实际情况 |
|---|---|
| 上传 MAC / 芯片 ID / IMEI / 设备指纹 | **没有**。MAC 只用在本机 SoftAP 名（`XianDial-XXXX`）与 IDF 私有分区，不外发 |
| 埋点 / 遥测 / 崩溃上报 / 使用统计 | **没有**。固件里不存在任何统计 SDK 的痕迹 |
| 检查更新 / 版本号上报 | **没有**。分区表无 OTA，无任何更新检查请求 |
| 把你的台单传回给我 | **没有**。台单只进 SD 卡，设备只把它当「要连接的对象」 |
| 把 WiFi 密码传出设备 | **没有**。配网页只连你家路由器 |

### 可以自己验证

固件不是黑盒，你可以直接扫：

```bash
# 固件里所有固定出站域名（只有一个）
strings -n 6 firmware.bin | grep -oE '[a-z0-9-]+(\.[a-z0-9-]+)*\.(com|net|org|cn|io)' | sort -u

# 确认没有 POST / PUT 出站（只应有 GET）
strings -n 6 firmware.bin | grep -iE 'POST|PUT' 
```

`ntp.aliyun.com` 之外的命中全部来自内置 CA 证书包（用来**验证别人**的 https 证书，不是要访问的地址）。

### 设备本地存了什么

| 位置 | 内容 |
|---|---|
| NVS `xs_wifi` | 你的 WiFi **名称与密码（明文）** |
| NVS `xs_fav` | 收藏的电台名 |
| NVS `xs_hist` | 收听历史 |
| NVS `xs_sleep` | 睡眠定时分钟数 |

**关于 WiFi 密码明文**：ESP-IDF 的 NVS 默认不加密，能用串口读出来。这是「家里的路由器」这个量级的取舍 —— 换来的是不用引第三方加密依赖、少占几百字节 flash。如果你的 WiFi 密码不宜这样存放，**不要用这台设备配网**，或在源码里开 `CONFIG_NVS_ENCRYPTION`（会增加 flash 占用）。

### 两件固件做不到的事（写在前面比事后解释好）

- **没有 HTTPS 证书校验的关闭开关。** 自用版有个 `?insecure` 后缀用于排障（区分「内存不够」和「证书链不认」），**发布版在编译期就把它去掉了**。要这个开关请自行编译。
- **串口日志会打印周围的 WiFi 名称**（连接前扫描的结果）。这是本地串口输出，不出网；但如果你把串口日志接到公共日志系统，那些名字会跟着走。
